# AI в Freshhead 0.2

Freshhead использует **локальный FashionCLIP**, а не чат-бота и не облачный API. Установленная на рабочем Windows-компьютере версия проверена с NVIDIA RTX 4070. Само наличие пункта AI в интерфейсе не означает, что все товары уже обработаны: раздел показывает фактическое количество изображений и очередь.

## Из чего состоит подбор

### 1. Фотография → вектор

Модель `patrickjohncyh/fashion-clip` загружается с фиксированной ревизией `7e3ba62ce16b379a1ab479346b66f192e76f51b7`, только в формате safetensors и без выполнения удалённого кода. Один товар получает нормализованный вектор из **512 чисел**. Близость этих векторов позволяет искать похожие вещи, даже когда название содержит только артикул.

Модель не генерирует изображение, не примеряет вещь и не рассуждает как LLM. Используется CLIP-представление фотографии. Оно может реагировать не только на одежду, но и на фон, освещение, позу и другие детали снимка. Авторы отдельно предупреждают о смещении модели в сторону стандартных товарных фото на белом фоне.

Источник модели и её ограничений: https://huggingface.co/patrickjohncyh/fashion-clip
Исследование авторов: https://doi.org/10.1038/s41598-022-23052-9

### 2. Неизвестные признаки → осторожные гипотезы

Фото сравнивается с заранее подготовленными текстовыми описаниями категорий, цветов, силуэта, рисунка, материала и визуального объёма обуви. Если разница косинусной близости двух лучших вариантов меньше 0.025, программа не принимает гипотезу. Этот порог — инженерная эвристика, **не калиброванная вероятность правильного ответа**.

Гипотезы сохраняются отдельно в `visual_attributes`, дополняют пропуски в текущих метаданных и помечаются как AI. Уже имеющиеся значения цвета, кроя и категории не заменяются догадками. Это не проверка состава ткани или точного размера. Гендер человека, внешность и мерки тела не определяются.

### 3. Твои лайки → персональный рейтинг

Вещь сравнивается с оценёнными вещами **своей категории**: обувь с обувью, брюки с брюками, верх с верхом. Для пары с проиндексированными фотографиями используется:

```text
similarity = 0.70 × max(0, image_cosine) + 0.30 × metadata_cosine
score = clamp(48 + 48 × average(top_3_liked_similarities)
                 − 38 × strongest_disliked_similarity, 0, 100)
```

При отсутствии одного из двух эмбеддингов используется только сравнение метаданных. Без лайков и дизлайков в категории начальная оценка равна 48 — это не персонализированная уверенность. Лайки не переобучают веса FashionCLIP: они меняют подбор ближайших положительных и отрицательных примеров. Поэтому реакция на новую оценку не требует тренировочного GPU-прохода.

Отдельная кнопка **«Похожие по фото»** ранжирует по визуальной близости, а не по совместимости в образе. Она учитывает категорию, настройки доступности/бюджета и дизлайки. Числа `/100` — внутренние сравнительные индексы, не вероятность понравиться.

### 4. Верх + брюки + обувь → отдельная оценка сочетания

Кандидаты из разных магазинов собираются по правилам палитры, пропорций, фактур и визуального веса. Доступны баланс, контраст и расслабленный силуэт. AI может дополнить недостающие признаки, но **оценка сочетания остаётся набором правил**, а не обученной моделью совместимости из гардеробов стилистов.

Например, для контрастного режима широкие брюки, компактный верх и низкопрофильная обувь могут получить надбавку. Это объяснение алгоритма, а не утверждение, что такой комплект всегда лучше массивной обуви. Происхождение правил и собственные гипотезы: [STYLE_GUIDE.md](STYLE_GUIDE.md).

## Управление

Открой **AI-зрение → Проанализировать новые фото**. На телефоне AI и магазины находятся в меню **⋯** сверху. Показаны прогресс, устройство, ошибки и число готовых фотографий. Можно остановить проход, запущенный этим сервером: уже записанные результаты остаются.

В настройках можно выключить использование AI без удаления индекса, изменить лимит фотографий и включить анализ после обновления магазинов. В новой установке автоматический запуск по умолчанию выключен. Один проход по умолчанию ограничен **192 фото**, допустимо 1–1000; очередь сначала обрабатывает оценённые вещи, затем чередует магазины и категории. Неизменившиеся фото не считаются заново. Изменение URL, модели или версии промптов инвалидирует старый результат.

Веса впервые скачиваются при запуске анализа. Сервер сам по себе не загружает модель в видеопамять. Вычисления идут в отдельном процессе; после окончания процесса GPU-память освобождается. Предусмотрен выбор CUDA → Apple MPS → CPU, но конкретный живой прогон этой версии проверен на CUDA/Windows. CPU и MPS не выдаются за проверенные на пользовательском устройстве.

## Установка на другом компьютере

Сначала запусти базовый Freshhead, затем `install-ai.bat` на Windows или `bash install-ai.sh` на macOS/Linux. Скрипт устанавливает зависимости в `.venv`, но не начинает скачивание весов или обход изображений без команды пользователя. API-ключи не требуются. Установка библиотек и модели занимает место на диске и расходует интернет-трафик.

Для проверенной CUDA-конфигурации Windows (команда выполняется из корня проекта):

```powershell
.\.venv\Scripts\python.exe -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -m pip install -r requirements-vision.txt
.\.venv\Scripts\python.exe -m freshhead index-images --limit 192
```

Официальные варианты сборок PyTorch: https://pytorch.org/get-started/previous-versions/

На macOS/Linux вместо `.venv\Scripts\python.exe` используй `.venv/bin/python`. Проверка установленного ускорения:

```python
import torch
print(torch.__version__, torch.cuda.is_available())
```

## Хранение и приватность

Фото скачиваются с публичных серверов магазинов, веса — из Hugging Face. Магазины и хостинг модели видят обычные сетевые запросы; полностью офлайн работает только уже подготовленный индекс, а не обновление товаров. Вызовов облачного inference API, отправки лайков или персональных фотографий в стороннюю AI-службу нет.

Вектора и признаки сохраняются в локальной SQLite-таблице `image_features`; история оценок остаётся в прежней базе. Веса хранятся в пользовательском кэше Hugging Face. `data/`, `.env`, логи и веса не публикуются в GitHub. Перед обновлением рабочей установки сохранена резервная копия базы. Телеметрия и неявная передача токена Hugging Face отключены в запускаемом AI-процессе.

Загрузчик изображений проверяет HTTPS, публичный DNS-адрес, robots.txt, перенаправления, размер ответа и число пикселей. Паузы между запросами соблюдаются. Отказ магазина, недоступный robots.txt или ошибка фото отображаются как пропуск; защита сайтов не обходится. Эта локальная однопользовательская программа не предназначена для открытого размещения в интернете.

## Что ещё не делает AI

Нет чата со стилистом, виртуальной примерки, персональных мерок, гарантии подходящего размера, проверки качества вещи, полного каталога всех магазинов или доказанной человеческими оценками эстетической точности. Задача версии 0.2 — реальное сравнение фотографий и понятная персонализация поверх честно отмеченных ограничений.
